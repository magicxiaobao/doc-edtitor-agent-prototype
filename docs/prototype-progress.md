## 3. 任务08 实现状态与核验区分

### 3.1 已实现（代码与架构就绪）
1. **统一动作权限规则（`permissionService`）**：
   - 全局抽象统一权限判定体系。主笔甲负责事实/文风/大纲确认、编辑正文、采纳建议、处理意见、恢复版本和定稿；审阅乙/丁仅可查阅文稿与发表意见批注，禁止改稿、批准大纲、恢复版本或定稿；供稿丙负责提交材料与补充说明，禁止直接改稿或批注。各阶段界面按钮与底层动作函数使用同一套权限逻辑。
2. **建议绑定与防错位覆盖机制**：
   - 修改建议严格绑定 `taskId`、`sourceDraftId`、`targetBlockId`、`baseContent` 与 `baseContentHash` 正文指纹。
   - 采纳时强制校验 `suggestion.targetBlockId`，严禁使用当前光标选中的 `activeBlock` 代替目标。当光标聚焦第二段时采纳第一段建议，准确更新第一段，绝不覆盖第二段。
   - 段落自建议生成后若被人工编辑修改，哈希指纹校验不通过，直接采纳被锁定并弹出明确冲突警示，防止覆盖人工文本。
   - 跨任务与跨版本隔离：切换任务或工作版本后，旧建议无法跨界采纳。
3. **工作副本与历史快照严格分离**：
   - 保存的历史快照版本与正式定稿（`isFinal: true`）具有只读不可篡改属性。
   - 定稿后重新编辑自动生成新的工作草稿（如 `v3.0 (工作草稿·重新编辑)`），清除当前任务定稿状态，同时完整保留此前定稿快照（内容、ID与定稿标记均稳定未改）。
   - 恢复历史版本创建全新的工作版本（如 `v3.0 (恢复自v1.0)`），原历史快照完好保留。
4. **版本快照元数据与历史导出防篡改**：
   - 每个草稿版本均记录生成当时的 `snapshotMetadata`（任务标题、统计期间、目标字数、大纲章节快照及事实快照）。
   - 历史版本导出（TXT 与 DOCX）优先读取当时快照中的章节标题与事实依据，不受主笔后续在大纲阶段修改标题的影响，严禁使用改动后的大纲重写历史版标题。
5. **审阅意见精细化处理与正文落实闭环**：
   - 审阅意见状态细分为 5 种：`pending`（待处理）、`accepted_pending_implementation`（决定采纳待落实）、`implemented`（已修改/已落实）、`rejected`（拒绝并说明）、`need_discussion`（待沟通）。
   - 仅做答复或统筹研判时，状态标记为“决定采纳·待落实正文”，**绝不虚假显示为“已采纳修改”**。
   - 采纳涉及文本修改建议时，弹出原文与建议对比弹窗，由主笔确认后真实修改正文段落并生成新版本，在意见记录中回写落实版本 ID（`implementationDraftId`）与落实段落 ID。
6. **批注基准原文记录与过期定位准确识别**：
   - 批注记录提出时的基准版本（`targetVersionId`）与段落原文（`baseParagraphText`）。
   - 当基准版本变更、段落删除或内容大幅重构后，系统显式提示“定位已过期”，保留当时基准文字，不静默挂接到变动后的段落。
   - 篇幅矛盾意见（审阅乙压缩 2000 字 vs 审阅丁增补案例）的协调记录区分“决定策略（待落实）”与“确认策略并落实到正文”。
7. **严格定稿准入核验机制**：
   - 无正文草稿时，定稿按钮明确禁用提示，不得弹出定稿确认或抛错。
   - 定稿前严格核验 6 项前置条件：①正文草稿存在、②主笔甲专属操作、③前序事实/文风/大纲审批有效、④指标口径冲突全部解决或排除、⑤重大审阅意见全部闭环处理、⑥无阻断级正文核校错误。
8. **RAG 与起草的取消、重试及运行标识**：
   - RAG 检索与正文起草均提供唯一运行标识（`runId`）、取消按钮与重试入口。
   - 任务切换或组件卸载时自动取消任务或隔离迟到结果，旧候选绝不污染新任务；取消不是成功，完整保留已有文稿与确认状态。

## 4. 任务07 实现状态与核验区分（往批记录保留）

### 3.1 已实现（代码与架构就绪）
1. **去除业务兜底硬编码**：彻底移除 `mockDraftService` 中作为兜底生成的 128、16、800、12 及固定 2026 年 1 至 9 月；正文生成严格遍历当前任务已确认大纲及其 `assignedFactIds`。无事实、无分配或缺材料时生成规范待补说明，不捏造任何数据。
2. **本期事实入稿条件严格化**：纳入正文的事实必须 `status === 'confirmed'`，属于当前统计期间，且具备原文出处依据或主笔核实补充；`selectedConflictValue` 无法绕过 `excluded` 或 `pending` 状态；历史 96 项（`isHistoricOnly`）与纯答案线索（`gap`）禁止入稿。
3. **120/128 冲突裁决与出处动态绑定**：面板同时展示双原文片段与候选来源；初始不预选大值、不预填结论，由主笔填写理由；采信 128 时主出处及反查严格指向 `EVD-02`，采信 120 时严格指向 `EVD-01`；支持明确排除冲突。
4. **最小材料到事实流程闭环**：粘贴/TXT 材料按自然段生成稳定 ID（`EVD-xxx-n`）与位置片段；支持基于片段建立待核事实，主笔可编辑数值、单位、统计期间、口径后确认；DOCX/PDF 格式仅记录元数据并标记“待接入解析”，不虚构正文提取。
5. **大纲事实分配与文风编辑**：大纲章节支持实际勾选分配或移除事实依据；文风规则支持编辑标题描述、排除与重新确认；文风未确认或事实快照无效时拦截大纲确认与正文生成，保留浏览权并展示原因。
6. **统一确认与失效联动**：快照冻结确认时的数值、单位、期间、用途与出处；事实撤销为 pending、口径变更、章节调整或文风修改后，下游大纲批准失效并拦截重新起草，正文工作台显式提示哪些段落需要复核，保护旧稿不被自动覆盖。
7. **局部改写事实不变量保护**：段落压缩、扩写、正式化与突出重点改写严格保护已有数值、单位与期间；模拟扩写仅优化表达与制度闭环，不捏造业务举措；25 场改写后保持 25 场，绝不回退至 16 场。

## 4. 人工验收与演示验证路径

1. **任务与参数校验**：
   - 顶部导航点击“快速载入演示场景” → 选择“1. 空白新建任务”。
   - 尝试创建任务，故意输入结束日期早于开始日期，观察系统弹出的精确日期校验拦截。
2. **材料与冲突裁决**：
   - 选择预置场景“2. 存在口径冲突 (120 vs 128)”。
   - 查看结构化事实清单，点击“裁决冲突”，对比科室甲120与科室乙128的原文位置，选择采信128并输入理由。
   - 切换到模拟RAG，测试“仅有生成答案(CLUE-01)”，观察线索状态及不自动生成假出处的行为。
   - 点击“确认本次事实清单”，生成锁定快照。
3. **文风与大纲规划**：
   - 进入阶段03，核对文风规则中的例句及2025年旧年份隔离；调整大纲章节建议字数并核验总字数偏差；点击“确认大纲”。
4. **正文起草与依据追溯**：
   - 进入阶段04，点击“重新生成候选稿”，观察正文中的重点任务自动采纳所裁决的128项。
   - 点击正文中的“16场、800人次”，右侧定位出处，并可在段落工具中体验“压缩精炼”与前后对比采纳。
5. **审阅协同与篇幅冲突**：
   - 顶部切换当前角色为“审阅乙”或“审阅丁”，进入阶段05，观察正文处于受限只读批注模式。
   - 主笔查看审阅乙（压缩到2000字）与审阅丁（增加详细案例）的冲突横幅，点击“协调裁决此冲突”完成闭环。
6. **核校演练与真实导出**：
   - 进入阶段06，点击“模拟注入800人错误”，观察核校引擎立刻报警并指出EVD-03台账为“800人次”。
   - 点击“一键纠正为800人次”，核校恢复绿色。
   - 点击“确认最终定稿”，锁定版本；点击“下载公文 Word (.docx) 文件”，验证真实本地生成的 .docx 文件。
