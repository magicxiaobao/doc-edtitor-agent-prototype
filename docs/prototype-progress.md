## 3. 任务09 实施状态逐项核验

### 3.1 已实现（代码与架构就绪）
1. **删除静态白名单与动态快照比对**：
   - 彻底删除原有 `allowedPatterns = ['120项', '128项', '16场', '800人次', ...]` 示例硬编码。
   - 改为从当前确认的事实快照（`factSnapshot`）及已登记证据材料片段中动态提取合法指标集。
   - 动态识别“采信128但正文写120”的冲突口径，定位至对应事实出处，标记为阻断项（`isBlocking: true`），阻止定稿。
   - 识别同段中“800人次，其中800人”的单位混淆，即便同一段落已有正确的“800人次”，仍能准确捕捉未带“次”的“800人”错误。
   - 数字提取逻辑精准避开“1至”、“1至9月”、“2026年”、“第1章”等期间与序号，不误将其提取为成效指标。
   - 未能可靠验证的句子（如仅有 RAG 问答线索的“服务满意度明显提升”）显式标记为“待人工核实”，绝不伪称核校通过。
2. **AuditIssue 类型完善、修正真实生效与忽略防护**：
   - 每一个核校问题均包含稳定 `issueId`、`taskId`、`draftId`、`blockId`、`location`、`originalText`、`evidenceText`、`suggestion`、`replacementText`、`isBlocking`。
   - 点击“接受更正”真实触发正文段落替换，生成带有版本记录的更新，段落文本实时改变。
   - “忽略提示”严格实施分类管制：阻断性重大偏差（如单位混淆、冲突口径）**禁止通用忽略**，界面明确禁用并提示必须修正；非阻断性提示（如定性线索说明）忽略必须填写具体业务理由，随草稿版本持久化归档。
3. **架构与工程门禁修复**：
   - 修复 `TaskSetupStage.tsx` 相对导入路径（`../../types`）。
   - 修复历史核校对象缺少 `blockId` 的问题。
   - 新增 `npm run typecheck` 命令，并调整 `build` 脚本为 `tsc --noEmit && vite build`，确保构建包含类型检查。
   - 生成并提交 `package-lock.json`，支持 `npm ci` 可复现构建。
4. **真实 DOCX 与 TXT 导出一致性**：
   - DOCX 与 TXT 共享相同的导出配置选项：`includeBody`（正文）、`includeEvidence`（依据出处）、`includeReviewLog`（审阅处理记录）。
   - 导出严格锁定指定的历史版本快照，读取当时生成该版本时的章节标题与事实快照，不受后续大纲修改影响。
   - DOCX 文件通过真实 OOXML 结构生成，包含符合公文规范的字号、首行缩进（480 twip）及附录审阅处理表格。
5. **SchemaVersion 迁移与数据损坏保护**：
   - 实现 `schemaVersion: 2` 存储规范；自动无损迁移旧版本数组格式，补全缺失的草稿元数据。
   - 数据损坏时隔离原始字符串至备份区，界面弹出可见告警横幅，提供“导出损坏JSON”和“重置预置场景”可恢复方案，杜绝静默丢稿。
   - 页面刷新后准确保留当前选中的任务、草稿、审阅记录及审批快照。
   - 保持“仍不把大文件装入 localStorage”原则，超长文档正文自动生成本地缓存预览，防范存储配额溢出。
6. **视觉与交互无障碍规范**：
   - 全局界面字体统一提升至至少 14px（`text-sm`），正文阅读与起草字号至少 16px（`text-base`），行高采用宽松倍率。
   - 针对 1440px、1280px、1024px 宽度适配，保障大屏与平板端正文排版空间。
   - 将演示模式、角色模拟切换、预置场景载入及错误注入工具整体迁移至顶部清晰标记的“演练辅助专区”；主笔操作界面全部使用真实业务动作文案（如“执行事实一致性比对”、“确认最终定稿”等）。
   - 弹窗增加键盘支持：支持 Esc 键快捷关闭、输入框自动聚焦与可见焦点光标（`focus:ring-2`）、显式 `htmlFor` 标签关联与明确错误校验提示。
