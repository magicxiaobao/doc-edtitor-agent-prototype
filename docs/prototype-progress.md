## 3. 任务10 实施状态逐项核验与接入细节

### 3.1 服务与页面组件深度接入
1. **定稿准入与状态共享**：
   - 界面定稿按钮 disabled 状态、提示文案、卡片核验指标与动作执行严格共用 `validateFinalizationConditions`。
   - 待处理（pending）、待落实（accepted_pending_implementation）与待沟通（need_discussion）意见均按版本血统关联检查，未闭环一律阻止定稿。
2. **统一正文变更规则与不可变分叉**：
   - 手工编辑、局部建议采纳、审阅意见落实、核校更正、重新起草候选采纳、历史版本恢复、核校演练注入全部共用 `applyDraftContentChange`。
   - 历史快照（`isHistoricalSnapshot: true, isWorkingDraft: false`）与定稿（`isFinal: true`）具有只读不可篡改语义，任何入口触发修改均自动分叉生成新工作草稿并记录 `sourceDraftId`。
3. **供稿候选与主笔核准联动**：
   - 供稿丙提交补充材料或摘录片段登记事实，严格保持为 `pending` 状态。
   - 主笔核准调用 `confirmFact`，严格校验有效来源文档（过滤 style_ref、2025年度、rag_clue/无原文/问答摘要）、结构化起止期间兼容性与冲突裁决状态。
   - 上游事实改动一致地重置下游审批状态（大纲审批失效、事实快照失效）。
4. **审阅协调真差异驱动与旧逻辑清理**：
   - 彻底删除 ReviewStage 中原有的 2026/128/12 与虚构案例旧写入逻辑。
   - 动态计算当前稿正文真实 diff 预览，经主笔研判核准后落实。
   - 零差异严格禁止标记为 `implemented`；若基准段落文本在协调后被人工编辑修改，触发基准冲突拦截，防止覆盖人工文本。
5. **结构化期间与真实案例过滤**：
   - 使用 `parsePeriodDateRange` 将年月、季度、月份转化为确定性时间跨度，严格判定超期与跨期数据。
   - 案例候选过滤历史文风（2025）及无原文线索，并过滤“暂无案例说明/关于暂无典型推进案例的说明”，防止无案例说明冒充真实案例。
6. **异步结果与任务边界防串扰**：
   - 异步生成与协调结果关联 `taskId`、`runId`、`baseDraftId`、`baseContentHash` 和 `upstreamSnapshotHash`。
   - 切换任务、组件卸载、点击取消或重试使旧结果立即失效，采纳时执行二次校验。
7. **指定版本ID缺失严格报错**：
   - 当调用参数显式指定版本ID但版本不存在时，严格抛出异常或返回明确错误，杜绝静默回退篡改首稿。
8. **事实/证据快照自足核校**：
   - 补充完善 `under_review` 预置场景快照元数据（含 `styleSnapshot`、`outlineSnapshot`）。
   - 即使当前任务事实被清空或删除，历史快照依据 `snapshotMetadata.factSnapshot.items` 仍可独立、自足地完成核校。
9. **精确指标核校与重核校保护**：
   - 支持同段多处单位混淆（如两处“800人”）字符定位索引，支持逐项修复。
   - 检出引用事实与正文数值改变（如“799人次”与800人次不符）。
   - 历史已记录的 `accepted` 状态不能放行正文中仍存在的错误；阻断性错误严禁被忽略。
10. **8种导出合法组合与持久化**：
    - TXT与DOCX完整支持正文/依据/审阅记录的 8 种组合（全开、单开、全关等）。
    - 存储实现运行时结构校验，捕获存储损坏并提供隔离备份；配额超限友好提示；长原文（超万字）完整持久化不截断。

### 3.2 复核7类边界问题专项修复
1. **异步结果与跨任务/卸载严格隔离（P0）**：
   - 绑定不可变 `runId`、`startingTaskId`、`baseDraftId` 与依据快照。
   - 卸载、任务切换、取消或重试时清理定时器，重置取消/运行标记，采纳时强校验 `pendingCandidate.taskId === task.id`，彻底杜绝串扰与卸载后写入。
2. **依据重建与快照原子更新、旧依据草稿定稿拦截（P0）**：
   - `applyDraftContentChange` 支持原子传入 `newSnapshotMetadata`，采纳重新起草候选时同步更新正文与冻结事实。
   - `validateFinalizationConditions` 增加依据血统比对，当任务事实快照重新核准变更后，基于旧依据的草稿严格阻止定稿。
3. **历史版本恢复生成新工作草稿并深拷贝依据（P1）**：
   - `handleRestoreDraft` 显式生成全新工作草稿（新ID、`sourceDraftId` 指向源历史版本），完整深拷贝所选版本的依据快照，恢复前工作草稿与历史版本均完整保留。
4. **审阅协调仅合并差异段落、保护未涉及段落人工编辑（P1）**：
   - `applyCoordinationDecision` 仅将 `diffPreview` 涉及的段落变更合并入最新工作稿，未涉及段落（如主笔修改的 BLK-02）完好保留；基准版本不匹配严格拒绝。
5. **统计期间解析严密性与动态表单回退（P1）**：
   - 修复正则支持“1月至9月”跨度；调整优先级使“前三季度”准确定位至1月1日（而非三季度7月1日）。
   - `isPeriodWithinTaskPeriod` 严查起始与结束边界，排除任务开始前的数据（如1-6月累计数据在4-9月任务中被拦截）。
   - 补充事实表单与片段登记根据任务起止日期动态计算默认期间（如二季度动态填“2026年4至6月”），避免表单被拒。
6. **历史审阅导出版本关联标记（P1）**：
   - TXT 与 DOCX 审阅记录附录显式标注每条意见的“针对版本”，并在导出配置中联动当前选定版本。
7. **损坏存储自动修复与可用文稿拯救恢复（P1）**：
   - 提供 `recoverTasksFromCorruptedBackup`，自动从备份中提取并修复缺失元数据的任务，在界面提供一键自动修复恢复按钮。

## 5. 第二轮代码复核（041ee1f 基线）四项缺口与两项验收闭环总结

1. **旧候选仍能覆盖人工修改（已闭环）**：
   - 在候选生成起点捕获当前正文 blocks 的内容哈希（`baseDraftContentHash`）及上游审批快照版本（`upstreamApprovalVersion`）。
   - 采纳时严格比较当前正文哈希；若正文在此期间有人工修改，严禁覆盖并弹出失效提示。同时校验上游事实、文风、大纲审批状态是否依然有效。
2. **定稿依据比较放行漏洞（已闭环）**：
   - `validateFinalizationConditions` 强制要求草稿必须具备完整的冻结事实快照（缺少快照严禁定稿）。
   - 按实际条目内容（`JSON.stringify(items)`）、哈希与确认时间综合比较，“确认时间相同”无法抵消内容差异（如当前120项、稿件128项时严格阻断）。
   - 纳入文风规范快照与大纲审批快照的版本与内容一致性校验。
3. **历史导出仍读取当前全部意见（已闭环）**：
   - `DraftVersion` 扩展 `frozenReviewComments` 字段；在保存版本快照及定稿时深拷贝冻结当下的审阅意见。
   - TXT 与 DOCX 导出优先读取目标草稿的 `frozenReviewComments`；历史版本不混入后续追加意见，也不受后续意见处理状态变化影响。
4. **存储恢复原路径与异常保护（已闭环）**：
   - `validateTaskStructure` 严格校验任务内部数组（drafts, facts, outline, documents, snippets, styleRules, reviewComments, auditIssues）及各草稿段落结构与 `referencedFactIds`。
   - 损坏隔离写入 `BACKUP_CORRUPTED_KEY` 时增加独立 `try...catch` 异常保护与内存回退，确保存储损坏与配额超限同时发生时不抛出未捕获异常。
   - `recoverTasksFromCorruptedBackup` 杜绝混入示例材料/事实数据，使用空结构与“待恢复”状态，完整保留用户真实原文，段落字段安全补齐并逐层校验。
5. **两项验收补充（已闭环）**：
   - `formatDefaultPeriodForTask` 与 `parsePeriodDateRange` 支持非整月起止（如 4月15日至6月15日）及跨年（如 2025年11月至2026年3月、2025年11月15日至2026年3月15日）的精准日期解析与合规校验。
   - `package.json` 中的 `npm test` 脚本已补齐 `test-task10.ts`；全量 4 个任务测试套件（Task 07 ~ Task 10）全部通过。
